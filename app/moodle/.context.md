Moodle application manifest — an open-source online learning platform built in PHP for creating and managing virtual learning environments.

## Summary

- manifest.yml — Application manifest defining PHP-based installation with admin and site-name configuration
- assets/ — Directory containing avatar, screenshots, and an .htaccess file copied into the install

## Constraints

- Requires PHP 8.3 and MariaDB services (PHP 8.3 is the minimum for Moodle 5.2).
- Downloads the human-readable tag archive `v5.2.3` (`github.com/moodle/moodle/archive/refs/tags/v5.2.3.tar.gz`) from the official GitHub mirror and verifies its SHA-256 digest before extraction; a mismatch aborts the install. The old `download.moodle.org` URL 302-redirects to `packaging.moodle.org`, a Cloudflare host that serves a "Moodle challenge" 403 to datacenter IPs, breaking CI. GitHub serves tag archives with a `moodle-<tag>/` prefix, so its digest differs from the equivalent commit archive even though the content tree is identical.
- The digest guard makes the tag pin as safe as a commit pin: if the tag is ever retargeted, the digest mismatches and the install fails closed. The version stays readable at a glance in the URL.
- Fresh installs only receive Moodle security updates when a human bumps the manifest: change the tag in the URL, recompute the archive's SHA-256, and update the guard digest. No bump automation exists in the repo.
- Moodle 5.x serves from the `public/` subdirectory; the install keeps the code in `/app/moodle_<uuid>` and symlinks the install directory to its `public/` dir. The GitHub archive extracts under a `moodle-<tag>/` prefix, so the tar step strips it into a `moodle/` dir.
- Requires admin user configuration (username, password, email) and site full/short names.
- Sets utf8mb4 collation on the database before install (avoids a charset mismatch).

## Guidance

- Installation runs Moodle's CLI installer (`admin/cli/install.php`) non-interactively; no web-based setup wizard is required.
- The `.htaccess` asset (routes everything through `r.php`) is copied into `public/`, not the code root.
- A `MoodleCron` job runs `admin/cli/cron.php` every minute; uninstall moves the code tree and data to `/app/.trash/` and removes the symlink.
- Uninstall tolerates both layouts: the current one with the code in `/app/moodle_<uuid>`, and the legacy 4.5 one with the files inside the install directory.
- Moodle data lives in `/app/<hostname>-moodledata`, outside the install directory.
